## 1. 现状结构分析

### 1.1 目录组织（`src/`）

```
app/         providers.tsx, router.tsx(推断), main.tsx        应用装配 + 路由
components/  glass/  common/  layout/  motion/  brand/         跨功能 UI 原语
features/    reader/  library/  settings/  notes/  search/     业务域（功能主战场）
             stats/  source/  graph/  command/
hooks/       use*.ts (≈50)                                   与渲染解耦的逻辑钩子
lib/         ipc.ts(单出口) · bindings.ts(生成) · local/(域文件) 通信 + 浏览器后端
stores/      zustand (≈22)：settings/reader/chrome/command-palette/toasts/…
styles/      globals.css                                      设计令牌 + 材质阶梯 + 关键帧
types/       ipc.ts · foliate-js.d.ts                          契约
vendor/      foliate-js (readest fork)                         vendored 渲染器
```

`features/reader/` 是绝对重心：**100+ 文件**，含共享宿主 `ReaderHost.tsx`(188 行) 与渲染分支 `PdfPageView`(25K) / `FoliateBookView`(86K) / `ReaderChapterView`(17K) / `SplitReader`(对照) / 编排巨石 `ReaderPage`(2936 行)。

### 1.2 技术栈（与文档一致）

React 19.3 · Vite 8（Rolldown，advancedChunks 分 vendor-react / vendor-router-query）· Tailwind v4（CSS-first `@theme`）· motion 14 · Radix（Dialog/Switch）· TanStack Query 5 · zustand 5 · pdfjs 6.4 · foliate-js（readest fork，配 paginator 修正）· Rust/Tauri 2 + SQLite。纯本地、AI Native、不打包数据集。

### 1.3 核心模块 / 页面 / 组件

- **阅读器**：`ReaderHost`（共享宿主）→ 按格式路由到 `FoliateBookView`(EPUB/FXL) / `PdfPageView`(PDF) / `ReaderChapterView`(FB2/CBZ/TXT/MD)。`SplitReader` 渲染两个 `ReaderHost` 实现对照阅读，通过 `pairLayout` 的 portal 把 active 那一边的控件「搬」到统一底栏。
- **书架/库**：`LibraryPage` → `ShelfGrid` + `ShelfHeader` + `BookCard` + 批量条 + 导入覆盖层 + 标签/书源对话框。
- **设置**：`SettingsPage`(1386 行) 按 section 组装，含键位、AI/同步、目录字体、书源、备份。
- **笔记/统计/搜索/书源/知识图谱/命令面板**：各自成域，命令面板（`command/`）走注册表 + `commandBoundTo` 问注册表转发键（见 `readerKeys.ts`）。
- **组件库**：`glass/`(button/input/overlay/panel/sidebar/surface) 四级材质；`common/`(QueryError/EmptyState/Markdown/ErrorBoundary)；`layout/`(TitleBar/NavList/PageHeader/UpdateBanner)；`motion/`(Reveal/IconSwap/BookCoverFlight)。

### 1.4 状态管理

三层清晰分工：

1. **zustand**：UI/偏好/会话态（`settings` 持久化、`reader`/`chrome` 阅读会话、`command-palette`、`toasts`、`book-handoff`、`commands`）。
2. **TanStack Query**：所有 IPC 读，`staleTime: 10s`，onSettled 失效 `["books"]`；写操作经 `ipc` 后 invalidate。
3. **useMemo**：派生/分组（`SearchPanel` 的命中分组、`SplitReader` 的 identity 发布）。

未启用 React Compiler → 手写 memo 是真实负担（非 bug）。

### 1.5 接口调用

`lib/ipc.ts` 单一出口封装全部 ~82 条命令（79 specta + 3 二进制手写）。web 构建在 `ipc.ts` 处换入 `lib/local/backend.ts`（IndexedDB 同命令名实现），上层 hook/query/缓存键**完全不变**——双构建仅差存储。深链单 scheme `fangce`。

## 核对结果（2026-10-31）

按 §5 的顺序执行时逐条核对过，**本审查的「必须修复」一档有四条与仓库实况不符**，一并记在这里，免得下一个人照着清单再查一遍。

| 条目                     | 核对结论   | 证据                                                                                                                                                         |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| F1「对照阅读零专用测试」 | **不成立** | `e2e/pair-reading.spec.ts` 356 行 5 个用例：开对、切 active（块点 / 纸面点两条路）、退出、面板归属、标尺归属、排版逐书                                       |
| E5「5 处 `as any`」      | **不成立** | `grep "as any" src` 的 5 条命中全是注释里的英文散文（"as any other"），真实 `as any` 为 0                                                                    |
| F2 的范围                | **写错了** | `SourceDialog` 里没有 `<select>`（`b7368b2` 已换成自绘 `SourcePicker`）；真正剩下的原生 `<select>` 只有 3 处：`ShelfToolbar` ×2、`SettingsPanel` 的 `Select` |
| E4（P1-12 侧栏语义）     | **已解**   | `NavList.Footer` 只有三个动作：折叠/展开、⌘K、设置                                                                                                           |

实际落地的：
